# SFLIX-20261120-010 – Fehler in den Testwerkzeugen aus der Erstprüfung 007 beheben
- Erstellt am: 2026-11-20
- Absender: Prüfung
- Empfänger: Entwicklung
- Priorität: HIGH
- Status: COMPLETED
- Übergabegrund: Begruendung HIGH: Ohne die Korrekturen 1 bis 3 funktioniert der dokumentierte App-Testablauf im Emulator nicht (App lädt keine Quelle).
- Aufgabenbeschreibung: Befunde aus SFLIX-20261120-007 (Reproduktion jeweils im Emulator STEFFLIX_API35 mit zwei fremden Emulatoren parallel):
  1. HIGH smb-testshare.ps1 Zeile 38: Emulator-Erkennung ohne -Serial schlägt immer fehl. Das zweite -match ('^STEFFLIX_') überschreibt $Matches, danach ist $Matches[1] leer, $Serial bleibt leer, adb reverse wird übersprungen (Warnung "Kein STEFFLIX-Emulator gefunden", obwohl emulator-5558 STEFFLIX_API35 lief). Lösung: Serial vor dem zweiten -match in eine Variable sichern (wie avd.ps1 $s).
  2. HIGH smb-testshare.ps1 Zeile 97 (und 64): In PowerShell 5.1 mit $ErrorActionPreference='Stop' wird stderr von adb trotz 2>$null zu einem NativeCommandError und bricht das Skript ab ("adb.exe: error: cannot bind listener: Permission denied"); der Rückfall auf adb root wird nie erreicht. Von Hand funktioniert der Ablauf (adb root, wait-for-device, reverse tcp:445 tcp:<Port>). Lösung: adb-Aufrufe mit möglichem stderr über cmd /c "... 2>&1" oder lokal $ErrorActionPreference='Continue', danach $LASTEXITCODE auswerten. Gleiches Muster in avd.ps1 (emu avd name, getprop 2>$null) prüfen; dort trat es im Test nicht auf.
  3. HIGH smb-testshare.py: impacket öffnet Dateien unter Windows mit os.open(pathName, mode) ohne O_BINARY (smbserver.py Zeilen 320, 2270, 3434). Textmodus: das erste Byte 0x1A gilt als Dateiende. 239 von 261 Dateien der Testumgebung kamen abgeschnitten an (z. B. thumbs\...\Staffel 1.jpg: 34525 Bytes, gelesen 59, Byte 59 = 0x1A); die App meldet "Datei unvollständig gelesen" (SmbSource.readAll) und lädt nicht. Lösung: in smb-testshare.py vor dem Serverstart os.open so umhüllen, dass O_BINARY ergänzt wird (Behelf der Prüfung im Scratchpad: os.open = lambda p, f, *a, **k: orig(p, f | getattr(os, "O_BINARY", 0), *a, **k); damit 261/261 vollständig und App-Ablauf bestanden).
  4. MEDIUM Standardport (DEC-340): -Port Standard 4445 auf 47123 ändern (Kommentarkopf, Docstring und argparse-Standard in smb-testshare.py, docs\TESTING.md). Remote-Debugging von WebView2 in docs\TESTING.md auf 47124 statt 9222.
  5. LOW Net.IsReleaseFolder (Desktop): leerer Pfad ergibt True, weil Path.Combine("", ...) gegen das Arbeitsverzeichnis aufgelöst wird (Test aus dem Projektordner). Praktisch kaum relevant (App.Root absolut); optional string.IsNullOrEmpty(baseDir) -> false. Nur zusammen mit einer ohnehin fälligen Desktop-Änderung.
  Nachtrag: Parallel wurde der Standardport auf 4455 gesetzt (smb-testshare.ps1, smb-testshare.py, docs/TESTING.md) und eine Pruefung auf belegte Ports ergaenzt. 4455 liegt ebenfalls nahe bei 4445; der Benutzer will ausdruecklich keine aehnlichen Ports: gemaess DEC-340 auf 47123 aendern (Belegt-Pruefung beibehalten). Punkte 1 bis 3 bestehen im aktuellen Stand weiter (Zeilen 38/39 und 104).
