# SFLIX-20261120-013 – Player: Next/Previous über Media Session (BiB, Medientasten)
- Erstellt am: 2026-11-20
- Absender: Planung
- Empfänger: Entwicklung
- Priorität: MEDIUM
- Status: COMPLETED
- Aufgabenbeschreibung: player.js nutzt die Media Session API noch nicht. navigator.mediaSession einrichten: Aktionen previoustrack/nexttrack an die bestehenden Funktionen von prevButton/nextButton binden (nur setzen, wenn ein vorheriges bzw. nächstes Video existiert, sonst Handler null, damit die Schaltfläche im BiB verschwindet), zusätzlich play/pause; Metadaten (Titel, Serie/Staffel/Folge, Plakat als artwork falls vorhanden) setzen und beim Wechsel nachführen. Gilt überall, wo der Player läuft (Desktop, Browser; App prüfen, darf nicht stören). Next/Previous im BiB muss im BiB weiterlaufen (BiB bleibt beim Videowechsel offen, falls technisch möglich; sonst Verhalten dokumentieren).
- Technischer Kontext: Benutzerentscheid 20.11.2026: Media Session überall zulassen. Unabhängig von SFLIX-20261120-011 (zurückgestellt) und Bewertung SFLIX-20261120-012 (Architekt). Bestehende Knöpfe: ui.prevButton/ui.nextButton um player.js Zeile 1642/1968.
  Ergänzung Benutzer 20.11.2026: Oben links zeigt das BiB 'Datei auf Ihrem Gerät'. Gewünscht ist der Videotitel. Im Test prüfen, ob die Media-Session-Metadaten (title) diese Anzeige im BiB von WebView2/Chromium ersetzen; falls nicht, nur festhalten (Lösung über eigenes BiB-Fenster, Auftrag SFLIX-20261120-012), keine Umgehung bauen.
  Ergänzung Benutzer 20.11.2026 (Bildschirmfoto BiB Desktop): Das BiB zeigt heute oben links S-Logo und 'Datei auf Ihrem Gerät', in der Mitte -10 s / Pause / +10 s, unten Fortschrittsleiste mit Zeit und Lautsprecher (nur Stumm/Laut). Diese Bedienelemente müssen erhalten bleiben: falls das Setzen der Media-Session-Handler die Sprungknöpfe verändert, seekbackward/seekforward (10 s) und seekto selbst setzen. Next/Previous kommen neben den Sprungknöpfen dazu.
- Betroffene Dateien: sflix_sys/js/player.js
