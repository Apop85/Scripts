# SFLIX-20261123-095 – Bild-im-Bild im Desktop schwarz: nur erstes Bild, danach nur Ton
- Erstellt am: 2026-11-23
- Absender: Architekt
- Empfänger: Entwicklung
- Priorität: MEDIUM
- Status: COMPLETED
- Aufgabenbeschreibung: Feststellung des Benutzers (23.11.2026): Beim Start des Bild-im-Bild zeigt das kleine Fenster nur das Bild beim Wechsel, danach schwarz bzw. stehend, der Ton läuft weiter. Noch offen (beim Benutzer nachfragen, falls nötig): eigenes BiB-Fenster (Document Picture-in-Picture, player.docpip) oder natives BiB; seit wann; App betroffen?
  Vermutete Ursache (Architekt, nicht nachgestellt): fillDocPip (player.js) verschiebt das Video ins BiB-Dokument, PlayerForm.OnPip minimiert seit 4.0.7 das Hauptfenster. Die Seite gilt für Chromium dann als verborgen, und die Hintergrund-Optimierung (BackgroundVideoTrackOptimization bzw. Drosselung verdeckter Fenster) schaltet die Videospur ab; nur der Ton läuft. Möglich auch eine geänderte WebView2-Laufzeit (Evergreen).
  1. In der Testumgebung nachstellen (SFLIX_DIR, eigenes BiB an und aus). Test: BiB starten, Hauptfenster wieder herstellen, ohne „Zurück zum Player“: läuft das Bild wieder, ist die Ursache bestätigt. GUI nur über Fenster-Nachrichten, Maus nur mit Freigabe des Benutzers.
  2. Lösung zuerst über Chromium-Argumente in CoreWebView2EnvironmentOptions (PlayerForm.cs, neben --autoplay-policy), z. B. --disable-features=BackgroundVideoTrackOptimization (und falls nötig --disable-backgrounding-occluded-windows bzw. --disable-renderer-backgrounding, so wenige wie möglich). Achtung: Die Argumente gelten für die ganze WebView2-Umgebung (gleicher UserDataFolder); prüfen, dass ein bereits laufender Prozess mit anderen Argumenten keinen Fehler auslöst.
  3. Hilft das nicht: Minimieren beim Start des BiB durch eine Lösung ersetzen, die die Seite sichtbar lässt, und vor einer Verhaltensänderung (Fenster nicht mehr minimieren) den Benutzer fragen (Verhalten aus 4.0.7 hat er so gewollt).
  4. Gegenprobe: normale Wiedergabe mit minimiertem Fenster ohne BiB (Ton, CPU-Last vertretbar), natives BiB als Rückfall, Bild-im-Bild der App unverändert.
  5. Version Desktop (Patch), Changelog über news.py, Prüfauftrag an Prüfung.
  Antworten des Benutzers (23.11.2026): 1. Betroffen ist das eigene BiB-Fenster (Document Picture-in-Picture). 2. Es hat frueher funktioniert; installiert ist Desktop 4.1.0 (Minimieren gibt es seit 4.0.7, also vermutlich geaenderte WebView2-Laufzeit). 3. Hauptfenster wieder herstellen bei laufendem BiB: Bild laeuft wieder -> Ursache (verborgene Seite, Videospur abgeschaltet) bestaetigt. 4. App noch nicht geprueft (Gegenprobe im Emulator genuegt).
- Technischer Kontext: Analyse des Architekten im Chat am 23.11.2026; Grundlage Changelog Desktop 4.0.7 (Fenster wird beim Start des BiB minimiert) und PlayerForm.cs Zeile 159 (CoreWebView2EnvironmentOptions) bzw. OnPip.

- Erwartetes Ergebnis: Das Bild-im-Bild im Desktop zeigt das laufende Video, auch wenn das Hauptfenster minimiert ist. Tests: Nachstellung vorher und nachher in der Testumgebung, Gegenproben aus Punkt 4, Probe-Kompilieren (csharp-pruefer).
- Durchgeführte Arbeiten: PlayerForm.InitWebView: zusaetzlich --disable-features=BackgroundVideoTrackOptimization,BackgroundVideoPauseOptimization (Umgebung WebView2); laeuft die Umgebung mit anderen Argumenten (ArgumentException oder COMException 0x8007139F), Rueckfall auf die bisherigen Argumente. Minimieren beim BiB bleibt (Punkt 3 nicht noetig, sofern die Pruefung das bestaetigt). DESKTOP.md, Changelog (Desktop 4.2.0).
