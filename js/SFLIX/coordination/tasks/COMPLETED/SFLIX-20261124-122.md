- Aufgabenbeschreibung: Fund aus der manuellen Pruefung A3 (SFLIX-20261124-112, DEC-373 Teil 4). Testdatei des Benutzers: .claude\jumpingFile.mp4 (1280x720 H.264, 23:24). ffprobe: Video-Luecke bei 0:15.07 von 10.07 s (Bild fehlt bis etwa 0:25.1, Ton laeuft durch). Nachgestellt im Desktop-Player (Test-Build 4.2.7, WebView2, ueber CDP) und im Vorschau-Browser. Ablauf: (a) Bei 0:14.71 meldet der Browser MediaError code 3 (PIPELINE_ERROR_DECODE, kein Netzwerkfehler). handleMediaError behandelt das wie einen Verbindungsabbruch: Meldung "Die Verbindung zur Datei ist unterbrochen. STEFFLIX versucht weiterzuspielen ..." fuer etwa 4 s, dann neu laden an 0:14.53. (b) Sofort wieder code 3 -> zweite Verbindungserkennung -> skipDamagedSpot: Hinweis "Datei bei 0:14 beschaedigt: 5 s uebersprungen", Fund gemeldet (Medien pruefen zeigt korrekt "bei 0:14, Laenge 10 s, Wiedergabe"). (c) FEHLER: Danach bleibt der Player stehen: currentTime 19.53, paused, readyState 1, video.error weiter code 3, 75 s lang keine weitere Meldung. skipDamagedSpot setzt nur currentTime und ruft play(); ein Element im Fehlerzustand laedt damit nicht neu. Ausserdem liegt 0:19.5 noch in der 10-s-Luecke, ein Sprung von 5 s reicht nicht.
  1. MEDIUM player.js skipDamagedSpot: Nach einem Fehler (video.error != null) die Datei neu laden (src neu setzen, sflixResume auf das Ziel, wie recoverConnection) statt nur currentTime zu setzen. Erwartung: Die Wiedergabe laeuft hinter der Stelle weiter oder es kommt der Hinweis "angehalten".
  2. MEDIUM Luecken laenger als 5 s: Liegt das Ziel noch in der Luecke, endet es wieder im Decodierfehler. Vorschlag: bekannte Luecke aus der gemeinsamen Liste (damaged.js, Stelle und Laenge aus Medien pruefen bzw. Downloader) verwenden und dahinter springen; sonst bei erneutem Fehler kurz hinter dem Ziel weiter springen (z. B. 5, 10, 20 s), statt die Zaehlung an einer neuen Stelle von vorne zu beginnen. Hoechstgrenze und Hinweis "angehalten" beibehalten. Falls das DEC-373 Teil 4 aendert: Entscheid mit dem Benutzer.
  3. LOW Meldung: MediaError code 3 (MEDIA_ERR_DECODE) bei einer laufenden Datei ist kein Verbindungsabbruch. Vorschlag: bei code 3 keine Meldung "Verbindung unterbrochen", sondern gleich als beschaedigte Stelle behandeln (ein Neuladen-Versuch ohne Meldung ist moeglich). Code 2 (NETWORK) und Haenger bleiben bei der Verbindungserkennung.
