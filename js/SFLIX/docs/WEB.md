# STEFFLIX – Weboberfläche

Dateien und Abläufe der Weboberfläche (`start.html`, `sflix_sys\`). Gelesen von der Rolle Entwicklung (bei Änderungen an der Weboberfläche), Architekt und Prüfung. Nur den nötigen Abschnitt lesen. Pflege: die Rolle, die eine Datei hinzufügt, löscht, umbenennt oder ihren Zweck ändert, im selben Schritt (`check_docs.py` prüft es).

## Grundsätze
- STEFFLIX läuft **nur über `file://`**: `start.html` per Doppelklick im Browser oder im Fenster von `STEFFLIX.exe` (WebView2, lädt ebenfalls `file://`). Kein Webserver, keine ES-Module, kein `fetch` auf lokale Dateien; Daten kommen über Skriptdateien (`data.js`, `renamed.js`, `version.js` …), Speicher nur über localStorage oder IndexedDB. Externe Daten (Changelog, neueste Versionen) nur von GitHub.
- Alle Funktionen sind global. Ladereihenfolge in `start.html`: core, storage, cards, pages, player, ui, main. Code beim Laden läuft nur in `main.js`.
- Dark Mode, keine Emojis (SVG-Symbole aus `iconShapes`). Farben Rot `#e8261a`, dunkel `#a81a0f` (CSS `--sflix-accent`).
- Die Android-App fügt `inject.js` ein und nutzt Namen aus STEFFLIX (Liste oben in `SFLIX_Tools\Android\app\src\main\assets\inject.js`): bei Umbenennungen nachführen (siehe `docs/ANDROID.md`).
- Neue oder entfallene Dateien der Weboberfläche in `SFLIX_Tools\Release\sflix_update.py` eintragen (`WEB_FILES`, `OBSOLETE_FILES`): Sie kommen über `checksums.json` ohne neuen Desktop zu den Nutzern (nur `start.html` und `sflix_sys`).

## `start.html`
Einstieg. Lädt `sflix_sys\sflix.css`, `sflix_sys\data.js`, `renamed.js`, `damaged.js`, `install.js`, `updater_info.js`, `license.js`, `version.js` und `sflix_sys\js\*.js`. Enthält das Markup von Hilfe (`#help`, Symbole per `<span class="helpIcon" data-icon="…">`, Versionstabelle STEFFLIX/Desktop/ffmpeg) und Einstellungen (`#settingsPage`: Darstellung, Sortierung, Startseite, Wiedergabe mit Intro und Abspann je Ordner, Datensicherung, Fehlerbehebung mit Prüfung und Diagnose, Android-App (`#android`: Vorstellung, Download-Knopf auf `STEFFLIX.apk` im GitHub-Repo), Lizenz (nur Anzeige), Zurücksetzen); beide werden per `buildSectionPage` in Abschnitte gegliedert. URL-Seiten: `HELP`, `SETTINGS`, `FAVORITES`, `SEARCH:…`, `LEVEL0:…`. Das Skript am Ende prüft je Programmdatei eine Funktion und die Markierung in der letzten Zeile (`sflixFileEndCore` … `sflixFileEndMain`, abgeschnittene Dateien) sowie `data`; fehlt etwas, blendet es `#loadingScreen` aus und zeigt den Hinweis (z-index 10001). Das Hintergrundbild des Ladescreens steht zwischen `/* ladehintergrund:start */` und `/* ladehintergrund:ende */` (erzeugt von `SFLIX_Tools\Bilder\ladehintergrund.py`).

## Übrige Dateien in `sflix_sys\`
| Datei | Zweck |
|---|---|
| `sflix.css` | Gesamtes Styling. Hintergrund `--sflix-bg-gradient` (Lichtkegel unter der Menüleiste), `--sflix-bg` `#101013`, `--sflix-bg-elevated` `#26262c`; Video im Querformat über `.sflixPlayer.isVideo.fitViewport` (`--fit-width`/`--fit-height`, nicht im Kinomodus); im Kinomodus (`html.playerCinema`) Scrollbar unsichtbar, solange die Leiste ausgeblendet ist (`cinemaScrolling`); feste Flächen: Video `aspect-ratio: 16 / 9`, Bilder in `#playerContainer:has(> #imageLink)` mit 72vh. |
| `version.js` | `var version = <alte Zahl>; var versionName = "x.y.z";` – alte Zahl zuerst für Installationen bis 2.04 (x + y/100 + z/10000). Desktop liest sie, `build_release` bzw. `/version-erhoehen` setzen sie (beide Zeilen, `versioning.version_js_text`). |
| `news.txt` | Changelog (HTML-Quelle). Pflege nur über `SFLIX_Tools\Release\news.py`. STEFFLIX vor 2.00 liest sie direkt. |
| `news.json` | Aus `news.txt` erzeugt (`create_news.py`): je Version `version`, `name`, je Eintrag `component` (stefflix/updater/app), `componentVersion`, `short`. Nie von Hand ändern. |
| `data.js` | Medienverzeichnis, erzeugt von „Daten einlesen“ (im Repo nur Muster). |
| `renamed.js` | Von „Daten einlesen“ erzeugt: umbenannte Pfade (`renamedPaths`). Nicht pushen. |
| `damaged.js` | Von STEFFLIX.exe geschrieben (DEC-374, seit 2.9.0): `var damagedMedia = { version, items: [{ path, size, gaps: [{ at, length, source, date }] }] }`, beschädigte Dateien aus Downloader, „Medien prüfen“ und Player. STEFFLIX liest nur (fehlt sie, ist die Liste leer). Nicht pushen. |
| `install.js` | Von STEFFLIX.exe erzeugt: `installId` (32 Hex) und `installFolder`. STEFFLIX nutzt damit die eigene IndexedDB `STEFFLIX-<installId>` (ohne Datei die gemeinsame `STEFFLIX`); gemeinsame Daten werden einmalig übernommen (`sharedDataImported`). Kopierter Ordner → neue Kennung, verschobener → gleiche. **Nie pushen oder kopieren.** |
| `license.js` | Von STEFFLIX.exe geschrieben: `var licenseFile = { key, confirmedFor }`. STEFFLIX liest nur. **Nie pushen oder weitergeben.** |
| `updater_info.js` | Von STEFFLIX.exe bei jedem Start: `var updaterInfo = { updater, ffmpeg }` (Hilfe, Diagnose, Hinweis auf neuen Desktop). Nicht pushen. |
| `updater_settings.json`, `folgen_cache.json`, `folgen_rueckgaengig.json`, `medien_cache.json`, `downloads.json`, `updater.log`, `player.log` | Lokale Dateien von STEFFLIX.exe (siehe `docs/DESKTOP.md`). Nicht pushen. |
| `sflix.gif` | Vorschau-Animation (18 MB), über die GitHub-Adresse eingebunden, nicht in der Testumgebung. |
| `sflix.js` | Platzhalter (seit 2.00 unbenutzt) für alte Updater; STEFFLIX.exe löscht ihn bei Nutzern. |
| `splash.svg` | Animation des Startbildschirms (auch für die App, `build.ps1` kopiert sie). |
| `ffmpeg\` | Alter Ort von ffmpeg (bei Nutzern bis 3.2); wird beim Start nach `%LOCALAPPDATA%\STEFFLIX\ffmpeg` verschoben. |
